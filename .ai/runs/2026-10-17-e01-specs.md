## Outcome

**Success:** both specs are drafted and ready for product-owner review. The fresh-context review returned "revise". Every finding was addressed:

- **High, pre-registration hijack through confirm-on-open.** This raised **Q9**. The product owner chose link + password + Confirm, which also signs the person in (AD7).
- **High, the navigation handler couldn't redirect to GitHub.** P7 now allows an `externalUrl` restricted to an allowlist of origins taken from config.
- **Medium:**
  - Raw tokens: `return_to` was dropped and travels in the link; logs drop query strings.
  - Unknown client IP: per-IP rules are skipped, a per-email sign-in limit was added, and `TRUST_PROXY` is assigned to Phase 2.
  - Phase 1 size and broken steps: Phase 1 was reordered so the gate lands in Step 1.10 together with the integration scenario updates, with an optional two-PR split (1A/1B).
  - P14 and P16 layering: the webhook wrapper moved to `app`, and events are emitted after the transaction resolves.
- **Low:**
  - #34 now closes in Phase 2.
  - `CrudForm` gains an additive `resetOnSuccess` prop.
  - The `BACKWARD_COMPATIBILITY.md` and engineering-standards stale text is added to Step 1.11.
  - Consistency fixes: the GitHub port in the inventory, `PasswordField` in Phase 2, the "replaced link" message.
  - Testability: `main(argv, env, deps)` for the CLI entry, `metadata.referrer`, the OAuth cookie's `SameSite=Lax`, a dummy hash on the confirmed sign-up path.

Not run: lint, typecheck, build and tests. There are no code changes; the deliverable is documents.
