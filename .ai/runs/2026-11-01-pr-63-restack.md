# PR #63 restack

## Request

Restack the existing PR #63 onto current `main` after the squash merges of PR
#62 and PR #64. Preserve the completed Phase 2 and Phase 3 implementations,
avoid duplicating Phase 1, resolve conflicts, follow the repository SDLC, and
leave PR #63 open.

## Plan

1. Claim the existing PR and work in an isolated worktree.
2. Merge current `main` without rewriting the PR branch.
3. Use PR #62's squash tree as Phase 1, then replay only the Phase 2 and Phase 3
   delta from the stacked branch.
4. Resolve documentation conflicts, verify the resulting tree and run the full
   configured validation gate.
5. Push the merge commit, retarget the existing PR to `main`, and report it
   without merging.

## Key decisions

- The restack is a merge rather than a rebase so the existing PR history is not
  rewritten.
- `db9764587717edbef480d3a32fc6942cdab346ee` is the last Phase 1 commit in the
  stacked ancestry. The tree applied on top of current `main` is the net delta
  from that commit through `3a7b5c7859fa191cb16c53df719268c9dbfcdc2d`,
  which contains the completed Phase 2 commits and PR #64's Phase 3 squash.
- Current `main` is authoritative for Phase 1 and its post-review fixes.

## Outcome

The conflicts were resolved with current `main` as the Phase 1 source of truth.
The resulting PR delta contains the completed Stripe onboarding and availability
slot implementations without a second Phase 1 delta. The configured local gate
passed:

- `npm run lint`
- `npm run typecheck`
- `npm run test:coverage` (2,072 tests; 100% statements, branches, functions and
  lines across every measured source file)
- `npm run build`

Push, PR retargeting and CI status are recorded on the PR.
