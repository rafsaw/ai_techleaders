# Setup checklist

How DevMentor walks someone through a multi-step setup: `/mentor` (E02 Flow 1), where a mentor
becomes bookable through profile, payouts and slots.

## 1. Problem it solves

Several steps depend on each other and some wait on someone else (Stripe). The mentor should
always know what is done, what is next and what is blocked, and why.

## 2. Where in the product

| Screen | Kit |
|---|---|
| `/mentor` | signed-in |

## 3. Built from

**Bookable status line**, **Setup checklist** with **Setup item**, **Payout status**.

## 4. Rules

| Rule | Source |
|---|---|
| A status line on top says, in one sentence, whether the mentor is bookable and names only what is missing. | E02 Flow 1 |
| One item per shipped phase, in order; each has a state in words and exactly one next action. | E02 Flow 1 |
| A locked item says why: *Save your profile first.* | E02 Flow 1 |
| The primary button goes to the first unfinished item with an action: go down the list and stop at the first step that is not done and that the mentor can act on now. A step that only waits (Stripe is checking the details) does not count; contacting the team when setup failed or Stripe blocked the account does count. Every other action is outline or a link. `SetupChecklist` works this out itself. | R01.6, P-M4 (proposal approved by Rafał), Q-SC1 option (2), decided by Rafał 2026-10-21 |
| So the screen has exactly one primary button while any step has an action, and none when every unfinished step is only waiting. | R01.6, Q-SC1 |
| The state is text in a badge of 1–3 words; a longer state goes under the title. | P-C10, E02 UI/UX |
| Item titles are level-2 headings under the page's `h1`. | WCAG 1.3.1 (axe `heading-order`) |

**Decided (Q-SC1, Rafał, 2026-10-21):** the first unfinished item with an action. After the
profile is saved, **Continue to Stripe** is the primary button and **Publish slots** is outline.
While Stripe checks the details, payouts has nothing to do, so **Publish slots** becomes primary
(*Waiting*). With slots already published as well, there is no primary button (*Waiting nothing to do*).
When setup failed or Stripe blocked the account, **Contact the DevMentor team** is the primary and
**Publish slots** is outline (*Blocked*; confirmed by Rafał 2026-10-21).

## 5. States

| State | Story |
|---|---|
| New mentor | *Playground* |
| Next: payouts | *Step payouts* |
| Next: slots | *Step slots* |
| Waiting on Stripe, slots to publish | *Waiting* |
| Waiting on Stripe, nothing to do | *Waiting nothing to do* |
| Blocked at Stripe, contact is the primary | *Blocked* |
| Done | *Done* |
| Phase 1 only | *Phase one* |
| 320 px | *Narrow* |
| Loading | not applicable: the page renders on the server from `MentorSetupDto` |
| Error | see **Provider status** (Stripe banners) |

## 6. Behaviour and accessibility

- The checklist is an ordered list named *Mentor setup*; each title is a heading, so screen
  reader users can jump between steps.
- The state is never colour alone (WCAG 1.4.1).

## 7. Code

```tsx
<h1 className="text-page-title">Mentor setup</h1>
<BookableStatusLine state={line} />
<SetupChecklist profile={profile} payouts={{ payout, startOnboarding, onOnboardingUrl, contactHref }} slots={slots} />
```

## 8. Do and don't

| Do | Don't | Why |
|---|---|---|
| *Not bookable yet: finish Stripe.* | a progress bar or "60% complete" | A02: no course or journey look |
| Say why an item is locked | grey it out silently | the mentor must know what unlocks it (E02 Flow 1) |
