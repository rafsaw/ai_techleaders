# Text field

`import { TextField } from "@devmentor/ui/frontend/forms/TextField"`

Public kit (Q1 = a, platform F3): plain Tailwind on the same tokens as the signed-in `Input` +
`Field`, with no shadcn or Base UI. Label, input, hint and error come as one component.

## 1. What it is for

A text field lets a signed-out visitor type a short value (name, email) and tells them what it
is for and what went wrong.

## 2. When to use

- `/sign-up`: display name and email; `/sign-in`: email (E01 UI/UX).
- Usually through `SchemaForm`, which wires values and errors for you.

## 3. When not to use

| Situation | Use instead | Source |
|---|---|---|
| A password | `PasswordField` | E01 AD6 |
| A signed-in or `/backend` page | `Input` + `Field` (shadcn kit) | Q1 |
| A value the user cannot change | plain text | P-C6 |
| Long text | none in the public kit yet (What is missing) | — |

## 4. Anatomy

| Part | Required | Notes |
|---|---|---|
| Label | yes | `text-label`, always visible, linked with `htmlFor`; the placeholder is only an example (prompt, Form pattern) |
| Input | yes | `h-control-md` 36 px, `rounded-control`, `border-input`, `text-control` (16 px below 768 px) |
| Hint | optional | `text-meta`, `muted-foreground`, under the input, visible before typing |
| Error | when invalid | `text-meta`, `destructive`, `role="alert"`; a list when there are several |

Same order and tokens as the signed-in `Field` (label, control, description, error).

| State | Look | Source |

| Disabled | `disabled` colours, no opacity; the reason in the hint | B2 |
| Loading, selected | not applicable; the form's submit button shows loading | P-C4 |

## 7. Behaviour and accessibility

- The label names the input; hint and error are linked with `aria-describedby`, the error sets `aria-invalid` (E01 UI/UX accessibility, WCAG 1.3.1, 3.3.1). Story *Long content, narrow* tests both.
- The error is `role="alert"`, like the signed-in `FieldError`.
- Pass `autoComplete` (`name`, `email`) so browsers can fill it (WCAG 1.3.5).
- Hit area 36 px high.

## 8. Content

- Label: a noun phrase without a colon (*Display name*, *Email*, P-C7).
- Hint: a rule or what happens with the value (*This is the name others see. You can change it.*).
- Error: what to do (*Enter a valid email address*), from the shared schema.
- Long values scroll inside the input; hint and error wrap.

## 10. API

| Prop | Type | Default | Description |
|---|---|---|---|
| `label` | `string` | — | visible label |
| `type` | `"text" \| "email"` | `"text"` | input type |
| `hint` | `ReactNode` | — | rule or example under the input |
| `errors` | `readonly string[]` | — | messages for this field |
| `id` | `string` | generated | input id |
| …rest | `<input>` props | — | `name`, `value`, `onChange`, `onBlur`, `autoComplete`, `disabled` |

## 11. Code

Minimal:

```tsx
<TextField label="Email" type="email" name="email" autoComplete="email" />
```

From the product (`/sign-up`), through `SchemaForm`:

```tsx
{ name: "displayName", label: "Display name", autoComplete: "name", hint: "This is the name others see. You can change it." }
```
