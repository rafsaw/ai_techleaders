# Sign-up form

`import { SignUpForm } from "@devmentor/ui/components/auth/SignUpForm"`

E01 product component for `/sign-up` (Flow 2), built from the public kit (F3) only: `Notice`,
`SchemaForm` (with `PasswordField`), `LinkButton`. Moved out of the Sign up screen story in E01
Phase 2, so the screen and the page render the same code.

## 1. What it is for

It lets a person without GitHub create an email account, with the password rule and the
no-reset warning (N03) shown before they type.

## 2. When to use

- `/sign-up` only. The page adds the validated `returnTo` to the request and moves on to
  `/sign-up/check-email` in `onSignedUp`.

## 3. When not to use

| Situation | Use instead | Source |
|---|---|---|
| Signing in | **Sign-in options** | E01 Flow 2 |
| Changing the display name later | the `/account` form (`CrudForm`) | E01 UI/UX |

## 7. Behaviour and accessibility

- The response is the same whether or not the email has an account (E01 Flow 2), so there is no
  "already registered" state.
- The page moves on only after the server answered (`onSignedUp` gets `{ email, emailSent }`).
- Technical failures (429, network, server) use the form's one error notice (SM-AC17).

## 8. Content

## 10. API

| Prop | Type | Description |
|---|---|---|
| `schema` | `ZodType<{ displayName, email, password }>` | `signUpSchema` without `returnTo` |
| `submit` | `(values, { signal }) => Promise<ApiResult<{ email, emailSent }>>` | an `apiCall` |
| `onSignedUp` | `({ email, emailSent }) => void` | after success |
| `signInHref` | `string` | `/sign-in` with `returnTo` |
| `invited` | `boolean` | `returnTo` is an invitation |

## 11. Code

```tsx
<SignUpForm
  schema={signUpSchema.omit({ returnTo: true })}
  submit={(values, { signal }) => apiCall("/api/auth/sign-up", { method: "POST", body: { ...values, returnTo }, signal })}
  onSignedUp={({ email, emailSent }) => router.push(checkEmailPath(email, emailSent, returnTo))}
  signInHref={signInHref}
  invited={returnTo?.startsWith("/invite/")}
/>
```
