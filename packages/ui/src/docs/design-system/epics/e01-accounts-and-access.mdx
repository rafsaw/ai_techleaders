# E01: Accounts and access

Visitors get an account, confirm an email address when necessary, and accept an invitation on the account that owns its email. The header then shows the areas that account can enter. Sources: backlog E01 (#28), E01 specification, Flows 1–3 and UI/UX.

## Work remaining in the product

Implement the E01 specification's three phases: authentication/session services and routes, actual schemas, account persistence, email confirmation and delivery, invitation management and acceptance. Build the application layouts and `/error` header; the Storybook frame is the approved P-SCR1 composition, not an installed app layout. Sources: E01 Implementation Plan; POSTEP “Do zrobienia poza design systemem”.

Before wiring `/account`, add the specified `CrudForm` `resetOnSuccess={false}` behaviour so a successful save retains the updated name. Keep the already implemented shared validation, error associations and password visibility control; do not reimplement them. The spec still needs the approved password-visibility decision recorded when Phase 2 is implemented. Sources: E01 Phase 1, POSTEP Q-CF1 and P-PF1.

The temporary truncated account name moves into an account menu when the approved Menu gap is resolved (POSTEP P-A4). See [What is missing](?path=/docs/design-system-what-is-missing--docs) for the complete backlog boundary.
