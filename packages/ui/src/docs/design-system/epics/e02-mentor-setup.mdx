# E02: Mentor setup

A mentor publishes a profile and two prices, completes Stripe onboarding, and publishes concrete start times. The setup page always identifies the next available action. Sources: backlog E02 (#29), E02 Flows 1–4; POSTEP Q-SC1.

## Work remaining in the product

Implement E02's profile/pricing, Stripe, and availability phases with their migrations, services, ports/adapters, authorization and real endpoints. Use the existing `CrudForm` `textarea` and `select` support; it is already implemented and should not be added again. Sources: E02 Implementation Plan; POSTEP stage 3 batch 5.

Create the app layouts, the public-profile `not-found.tsx`, core's `formatMoney` and the colocated `LocalTime` formatter. Storybook supplies formatted strings; it does not implement those app responsibilities. Confirm the real contact destination for blocked/failed payout setup before passing `contactHref`. Record P-SCR5 in the E02 specification. Sources: E02 UI/UX and P17; POSTEP “Do zrobienia poza design systemem”.

At E04, add the booking action and keep it visible above the fold even with a long profile. The current narrow public profile puts prices after the description; no booking control exists yet. Source: POSTEP P-DV decisions and E02 MD5. See [What is missing](?path=/docs/design-system-what-is-missing--docs).
