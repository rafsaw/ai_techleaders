# Build a DevMentor screen

DevMentor is concrete, dense and readable: clear hierarchy helps a developer find a mentor or manage availability. Warm neutral surfaces and direct, conversational English keep the product human. One main action leads to the next step, with public work as the trust signal and no ratings, sales pressure or decorative AI imagery. Sources: R01.1–R01.7, A01–A08, Q5.

**Character:** concrete · dense · readable · warm · conversational.
**Avoid:** generic · showy · noisy · cold · sales-driven. Source: approved reference character words.

## Five steps

1. Find a [pattern](?path=/docs/patterns-form--docs) and the relevant [epic](?path=/docs/design-system-epics-e01-accounts-and-access--docs); follow its linked screen state map. Source: prompt stage 4.
2. [Choose the component](?path=/docs/design-system-how-to-choose--docs). Public pages use the Tailwind-only public kit; signed-in and backend pages use the signed-in kit. Source: Q1(a), F3.
3. Use [semantic tokens](?path=/docs/foundations-color--docs) for purpose, type roles for hierarchy and relation spacing for layout. Source: Z6, T1–T8, P-T1–3, P-L1–4.
4. Design loading, empty, error, partial, many and long-content states. Forms also need API pending, field error, server error, network failure and confirmed success. Source: prompt stage 3.
5. Check [what to avoid](?path=/docs/design-system-what-to-avoid--docs), keyboard focus, both themes and 320/768/1440 px. Source: prompt stages 4–5, WCAG 2.1.1, 2.4.7, 1.4.10.

## Shared behavior and boundaries

Use `useSchemaForm` from `@devmentor/ui/forms/useSchemaForm` for form behavior and `apiCall` / `apiCallOrThrow` from `@devmentor/ui/api/apiCall` for `/api/*` (F2, reusable API/UI layer). Use `cn` from `@devmentor/ui/lib/utils` to preserve the custom token utilities (existing package contract). These are behavior helpers, not visual components.

Stories use simulated API responses and replacement schemas; they do not implement application authentication, persistence, Stripe or routing. Read [What is missing](?path=/docs/design-system-what-is-missing--docs) before implementing. Source: POSTEP stage 3 limitations.

Source key: R/A/K = `lekcja-06/referencje.md`; T/Z/C = `lekcja-06/tokeny.md`; D/N = `.ai/specs/product-brief.md`; E01/E02 = their specs; F/P17 = platform primitives; Q/B/P-* = approved decisions in `packages/ui/POSTEP.md`. WCAG and WAI-ARIA APG identify accessibility requirements. Proposed guidance is explicitly labelled.
